# Jarvis voice agent implementation plan

> Execute inline using superpowers:executing-plans; user requests direct implementation after uploading current project. Baseline main/release is already uploaded. Work on feature/jarvis.

**Goal:** Wake with 贾维斯 and use natural language to open installed apps, browse app list, reach settings/network, and ask the configured AI, preserving hand/gaze/manual controls.
**Architecture:** Vosk Chinese ASR runs on-device in a foreground microphone service. Wake-gated bounded events wake the Unity workspace and feed a tested local intent parser plus optional cloud planner. A fixed allowlist dispatches app/catalog/status/settings tools; network credentials remain manual and local. No arbitrary shell, install/uninstall or automated account actions.
**Tech:** Android7/API25 ARMv7, Vosk0.3.75/JNA5.18.1, vosk-model-small-cn-0.22, Unity6 C# spatial UI, existing multi-provider CloudAiClient.
**Spec:** User latest request, docs/development-context.md constraints; retain silent output until user requests speech output.

## Global constraints
- No speech playback. Local microphone decoding, no audio storage/upload by default.
- Existing API keys stay encrypted; absent credentials still permit local wake/basic controls.
- Preserve original packages/calibration and verified releases. Reapply HOME after each update.
- Keep controller and gaze, manual network keyboard/settings.

## Review focus
- False wake/duplicate utterances, timeout/cancel, ambiguous app labels.
- Stale cloud results never execute after cancellation, and unsupported tool names are denied.
- Background app launch/pause must retain voice service while Unity resumes only on actual wake.
- Models/keys/audio excluded from Git where appropriate; official model hashes pinned.
- Microphone/ASR tested separately from intent parser; synthetic fixture is not a claim of real-user accuracy.

# 备份与恢复

## 当前基线

本次备份是在静音、热点连接、自动校时、手柄配对等操作之后建立的当前状态快照，不是操作前的原始出厂状态。

`tools/backup_baseline.py` 每次生成独立时间目录，不覆盖旧备份：

- 原始 sdk/、Export_apk/ 全文件复制；每个文件比对源文件与副本 SHA-256。
- 从设备拉取原厂启动器、设置、SDK 示例、Leap 服务及两种校准应用 APK，用设备提供的 SHA-1 工具核对传输一致性，同时在本地清单记录 SHA-256。
- 记录当前包信息、禁用包、系统属性、音频、相机、显示及选定设置。
- 备份内部与 docs/baselines/ 保存相同清单。保留清单与实际副本一起使用。

## 限制

本次没有 root、没有刷写分区，也没有备份应用私有数据、账号、完整校准数据、Bootloader 或完整固件。APK 备份不保证恢复应用数据或救回刷机失败的设备。

副本与项目都在 F 盘，可用于回退误改，但不能抵御该磁盘整体损坏。完整固件恢复方案确认之前，不进行刷机或系统分区修改。

## 后续改动

每个独立改动在安装或部署前保存对应当前 APK、版本、权限与设置，明确记录逆操作。新应用采用独立包名，避免覆盖原厂应用。源码和说明通过本地 Git 提交；构建物及设备快照留在备份目录。

Git 回退源码不会自动回退设备；设备恢复需要按对应改动的记录执行。恢复 APK 前核对签名、版本和包名，不默认卸载，不默认清除数据。相机与麦克风实际采集、云端上传的范围应在应用界面中明确，并提供停止控制。

源码已上传用户指定的 GitHub 仓库 cbob9581-dotcom/Realmax-AR，发布 APK 位于 Releases。密钥、账号、录音、照片、应用私有数据不进入 Git。

## 校准文件检查

旧 SDK 引用 `/sdcard/LMConfig.txt` 与 `/sdcard/Android/data/com.realmax.launcher/files/ipdinfo`；2026-11-09 检查时两者均不存在。这不代表设备没有校准，而是校准可能位于其他版本路径或私有区域；本次备份不能声称已覆盖校准数据。
